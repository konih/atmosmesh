# Stories

Each story is an implementation contract. The roadmap contains only ordering and status; the story
file owns scope, acceptance criteria, validation, and evidence.

## Rules

- Claim only a `Ready` story whose dependencies are done.
- Change its roadmap status to `In flight` before implementation.
- Do not weaken acceptance criteria to fit an implementation.
- Record commands, photos, measurements, screenshots, or logs under `Evidence`.
- Mark `Done` only when every required criterion is satisfied.
- Optional stories require explicit reprioritization.

Use [STORY-TEMPLATE.md](STORY-TEMPLATE.md) for new work.
