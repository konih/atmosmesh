# V15-03 — Grove OLED, BMP180 and DHT11 bring-up

- **Status:** Blocked
- **Priority:** P0
- **Depends on:** V15-02; DHT11 wiring correction and visual OLED confirmation remain
- **Objective:** Sample the fitted sensors, show trustworthy values/health on the 128×32 OLED and
  emit actionable serial diagnostics.

## Scope

- Explicit `Wire.begin(GPIO4, GPIO0)` shared bus setup.
- SSD1306 128×32 at 0x3C/0x3D, BMP180 at 0x77 and DHT11 on profile GPIO14.
- Distinguish unavailable/failed readings from a valid numeric zero.

## Out of scope

- Soil, light, sound, Wi-Fi/MQTT and flashing from this implementation lane.

## Acceptance criteria

- [x] Firmware compiles for the detected ESP8266 flash geometry.
- [x] Native tests cover present, partial and all-missing OLED/serial health states.
- [x] Current firmware startup emits display name, stable product ID, variant, station ID, exact
  pins, GPIO0 warning and per-device init result.
- [ ] A hardware capture observes the new explicit `product_id` field after a later reviewed flash.
- [x] Reviewed image flashes and boots with the expected product identity and pin configuration.
- [x] BMP180 produces stable runtime samples.
- [ ] OLED pixels are visually confirmed (I²C/controller initialization alone is insufficient).
- [ ] DHT11 produces valid readings.

## Validation plan

Native and build validation preceded independent review and one coordinator-run flash. For the
remaining work, verify the physical DHT11 DATA joint/pin, 3.3 V/GND orientation and 4.7–10 kΩ
pull-up or module resistor. Then capture valid DHT samples and visually confirm OLED pixels.

## Evidence

- 2026-08-24 `task build-grove`: success for NodeMCU v2, ESP8266 80 MHz, 4 MB flash; no upload.
- Native formatter tests prove valid zero is displayed as zero while invalid sensor state is
  displayed as dashes/`ERR`.
- `src/products/atmosmesh_grove_v1_5.cpp` explicitly uses `Wire.begin(4, 0)`, initializes OLED
  candidates 0x3C/0x3D and BMP180 0x77, and logs identity, wiring, GPIO0 boot warning and health.
- Every sample probes BMP180 address 0x77. Address loss invalidates prior readings before render;
  address recovery reinitializes the sensor and restores the explicit D2/D3 bus before reading.
- **Flash pass, 2026-08-24:** after explicit authorization and independent approval of `a681990`,
  `ESP_PORT=/dev/cu.usbserial-0001 task flash-v1-5` wrote 287,920 bytes, verified the hash and hard
  reset. Esptool identified the same ESP8266EX, 26 MHz crystal and 4 MB flash recorded earlier.
- **Boot pass:** product `AtmosMesh Grove`, variant `atmosmesh-v1.5`, station ID
  `atmosmesh-grove-0001`; I²C reported SDA=D2/GPIO4, SCL=D3/GPIO0 at 100 kHz plus the GPIO0 warning.
  This captured `a681990` banner did **not** contain a distinct stable product ID.
- **OLED partial:** `oled: ok addr=0x3C geometry=128x32` proves I²C/controller initialization.
  The operator has not yet visually confirmed pixels.
- **BMP180 pass:** `bmp180: ok addr=0x77`; five stable samples reported 25.1 °C and
  984.2–984.3 hPa.
- **DHT11 fail/blocker:** initialization used profile D5/GPIO14, but every observed cycle logged
  `dht11: error reading unavailable`. Cause is unknown; no temperature/humidity value is claimed.
- **Identity follow-up:** review required stable `product_id=atmosmesh-grove-v1.5` to be separate
  from `variant=atmosmesh-v1.5`. Native tests and the follow-up build cover the corrected contract;
  it has not been flashed or observed on hardware.
- The former AT firmware was replaced under authorization. AtmosMesh v1/ESP32 was untouched.
