# V15-02 — Shared multi-variant firmware architecture

- **Status:** Done
- **Priority:** P0
- **Depends on:** V15-01
- **Objective:** Build ESP32 v1 and ESP8266 Grove v1.5 from one PlatformIO project without cloning
  the complete ESP32 application.

## Scope

- Add a 4 MB NodeMCU-style ESP8266 PlatformIO environment.
- Add a thin Grove entrypoint/profile and shared pure formatting/domain behavior while preserving
  the existing ESP32 entrypoint.
- Name both product composition roots and add compile-time identity metadata for both.
- Add canonical product environments/tasks and retain existing compatibility commands.
- Propose and document the multi-product composition ADR.

## Out of scope

- Physical upload, MQTT/Wi-Fi, sensor calibration, or refactoring unrelated ESP32 subsystems.

## Acceptance criteria

- [x] Native tests prove Grove identity, pins, health formatting and missing-value behavior.
- [x] Native tests prove stable identity/profile metadata for both first-class products.
- [x] Both composition roots are explicitly named under `src/products/`; native excludes them.
- [x] ADR-0001 records context, decision, alternatives, consequences, migration and validation.
- [x] Canonical builds, `build-all`, compatibility builds and repository gates pass.
- [x] No secrets or generated binaries are tracked.

## Validation plan

Add failing native tests before new profile/utility behavior. Pure source moves and documentation
use build/gate evidence rather than contrived tests. Build each canonical and compatibility target.
