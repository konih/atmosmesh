# V15-05 — Grove MQTT and Home Assistant discovery

- **Status:** Blocked on reviewed hardware/network validation
- **Priority:** P1
- **Depends on:** V15-02 and V15-04 domain contract
- **Objective:** Publish the Grove environment and optional raw RC light response through the
  existing ID-based MQTT/Home Assistant model without cloning the ESP32 contract logic.

## Scope

- Reuse generated, gitignored Wi-Fi/MQTT credentials for both products.
- Add a thin ESP8266WiFi/PubSubClient transport over shared host-tested contract/session behavior.
- Use stable product ID `atmosmesh-grove-v1.5` and station ID `atmosmesh-grove-0001`.
- Publish retained offline LWT/online availability, state, and retained discovery on every connect.
- Cover temperature, humidity, pressure and uncalibrated `light_charge_us` discovery entities.
- Keep sensor sampling/OLED alive when credentials, Wi-Fi or broker are unavailable.

## Out of scope

- TLS, remote commands, room names, lux/illuminance, calibration, changing the AtmosMesh v1
  payload/runtime contract, or storing credentials in Git.

## Acceptance criteria

- [x] Native tests prove Grove topics, IDs, state JSON, valid-zero vs unavailable omission, the four
  original HA entities plus V15-06's raw-soil extension, retained availability/discovery, reconnect
  discovery replay and capped backoff.
- [x] Light discovery is explicitly an uncalibrated RC charge/response time in `µs`, with no
  illuminance device class or lux claim.
- [x] Grove transport uses retained offline LWT and online publication, and does bounded reconnect
  work without blocking the sensor/OLED schedule indefinitely.
- [x] Missing credentials disable networking with an actionable diagnostic while local sensing and
  display continue.
- [x] Existing AtmosMesh v1 tests, build, topics, payloads and pins remain unchanged.
- [x] No credential, network address or generated `secrets.hpp` is tracked.
- [ ] Reviewed hardware evidence covers connection, retained LWT/online, all five HA entities and
  continued local sampling during controlled Wi-Fi/broker loss.

## Validation plan

First add failing native contract/session tests. Parameterize shared identity/discovery/session
behavior while preserving v1 wrappers, then add the thin ESP8266 transport. Run native, both
canonical builds, compatibility builds, repository checks and secret/status inspection. Hardware
Wi-Fi/MQTT validation requires the coordinator to reconnect the USB serial device and flash the
already-approved product image.

## Evidence

- **Red, 2026-08-24:** native compilation failed on missing Grove product contract/state/session
  APIs. A later focused red test failed on the missing host-testable retained-offline will config.
- **Review-fix red, 2026-08-24:** regressions failed to compile against the missing shared DNS/TCP
  budget policy and publish-success acknowledgement. The state-loss regression also proved the old
  tick cleared pending state before an earlier discovery publication could fail.
- **Green, 2026-08-24:** native tests cover stable Grove IDs/topics, valid-zero environment fields,
  omitted invalid optional readings, retained will/online/discovery, reconnect replay and the
  existing 1–30 s capped session backoff. V15-06 extends the original four discovery entities with
  a fifth raw soil ADC diagnostic while preserving the same session behavior.
- Shared contract/discovery/session utilities now accept a product contract while their existing

  ESP8266WiFi/PubSubClient 2.8 transport. A bounded client override gives DNS and TCP one shared
  1000 ms budget; the MQTT response wait is separately limited to one second. Diagnostics state both
  bounds instead of implying PubSubClient's response timeout also bounded TCP setup.
- Session ticks retain pending state until the transport explicitly acknowledges successful state
  publication. A discovery/online failure disconnects and replays discovery without losing the last
  queued state.
- The main checkout has operator-managed `.envrc`; both product builds use the existing generator.
  Generator diagnostics no longer print SSID, broker address, username or password.
