# V15-10 — Grove status LED stuck red/amber (never healthy green)

- **Status:** Ready
- **Priority:** P1
- **Milestone:** Grove v1.5 field correction
- **Depends on:** V15-09 software (merged); D-021 calibration flags already on the Grove env

## User story

As the operator looking at the Grove bi-color LED, I want it to reach green when the node is
healthy, MQTT is up, and soil is in the acceptable band, so that red/amber mean a real problem
instead of the steady state.

## Outcome

The installed LED shows green in the known-good case, and red/amber only for the documented
priority reasons (core fault, MQTT configured-but-offline, dry soil, warning/uncalibrated band).
Serial `soil-led-status` explains the colour that is lit.

## In scope

- Capture serial `soil-led-status` / reason lines while the LED is stuck red or yellow/amber.
- Determine which priority branch is holding the colour (sensor fault, MQTT offline, soil dry,
  calibration/warning band, polarity/wiring) versus a drive bug.
- Fix firmware, config, calibration thresholds, or wiring as indicated by that evidence.
- Reconfirm common-anode D6 red / D0 green mapping on the installed board if polarity is again
  suspect.

## Out of scope

- ENV-01 enclosure temperature work (separate)
- Changing MQTT soil schema to percentages
- AtmosMesh v1 / Aqua LED behavior (Aqua has no this LED)

## Acceptance criteria

- [ ] Given the stuck LED, when serial diagnostics are captured, then Evidence names the
      `reason=` that was active (not a guess).
- [ ] Given a known-good window (core sensors OK, MQTT connected, soil raw in the D-021
      acceptable band), when the LED is observed, then it is green — not red or amber.
- [ ] Given a forced fault (e.g. MQTT down or soil raw in dry band), when the LED is observed, then
      it returns to red or amber per D-014/D-018 priority.
- [ ] Given the fix, when native soil-LED priority tests run, then they still pass; any new branch
      gets a failing-then-passing test first.

## Validation

- Automated: existing `test_soil_led_*` suite + any new case for the bug found.
- Manual: visual LED colour with matching serial reason; operator confirms green is actually green
  on the installed common-anode wiring.
- Failure/edge case: if soil never enters the acceptable band because the plant is dry or the
  D-021 cutoffs are wrong for this pot, fix thresholds or watering — do not force green.

## Evidence

Operator, 2026-08-31: Grove sensor LED is not working correctly — it is always red/yellow.
