# AU-07 — Open-Meteo: pick a place on the screen, get weather and a clock

- **Status:** Ready
- **Priority:** P1
- **Milestone:** Aura v1
- **Depends on:** AU-05

## User story

As the recipient, I want to set my town on the device itself and see the outdoor weather beside
the indoor air, so that the station is useful before I have decided to care about VOC numbers.

## Outcome

Open-Meteo, chosen because it needs **no account and no API key** — a key would have to be either
baked into a gift or typed on a resistive keyboard, and both are unacceptable.

| Purpose | Endpoint |
| --- | --- |
| place search | `geocoding-api.open-meteo.com/v1/search?name=<query>&count=5` |
| forecast | `api.open-meteo.com/v1/forecast?latitude=&longitude=&current=...` |
| clock | SNTP, once Wi-Fi is up |

Latitude, longitude and the display name are stored in NVS `globals`, so the choice survives a
power cut and the recipient sets it once.

## Screens

1. **Search** — a text field and keyboard; type a few letters of a town.
2. **Results** — up to five matches with country and region, because "Springfield" is not unique.
3. **Confirm** — the chosen name is what appears on the status strip.

## Rules

- **Never block the UI on the network.** Fetches run from a `script` with a timeout; LVGL keeps
  running throughout. A failed fetch leaves the last forecast with its age, or nothing at all.
- **Refresh every 15 minutes**, not more. This is a free public API used without an account.
- **The outdoor strip disappears when there is no data.** An empty row is worse than no row.
- No geolocation-by-IP. The recipient picks their town; the device does not guess.

## Acceptance criteria

1. A place set on the screen survives a power cut.
2. With Wi-Fi down, the Now screen renders and the outdoor strip is absent — G4.
3. A search with no matches says so rather than showing an empty list.
4. The clock is hidden until SNTP has actually synced; a wrong clock is worse than none.
5. TLS is measured against the flash budget before it is assumed to fit.
