# AU-08 — Optional MQTT and Home Assistant discovery, off by default

- **Status:** Ready
- **Priority:** P2
- **Milestone:** Aura v1
- **Depends on:** AU-06

## User story

As the operator, I want my own units to appear in Home Assistant, without the gifted units
talking to anything at all unless their recipient asks.

## Outcome

MQTT is **off by default and enabled from the settings screen.** A gift that silently connects to
a broker is a gift that leaks its owner's presence to someone else's server.

Topics follow the existing D-007 contract: `home/air/atmosmesh-aura-<id>/…`, values with explicit
units, missing distinguished from zero.

## The credential question

D-038 records the operator's decision to ship the fleet MQTT credential to trusted recipients,
along with the counterpoint that was not accepted: a fleet-wide credential in unencrypted NVS has
fleet-wide blast radius, and rotating it means reflashing every unit. That trade stands, but this
story narrows it — **MQTT off by default means the credential is never used unless someone turns
it on**, which removes most of the exposure without reopening the decision.

## Acceptance criteria

1. A factory unit publishes nothing until MQTT is enabled on the screen.
2. No topic or entity name contains `co2` or `ppm` — the D-002 guard applies to MQTT too.
3. Home Assistant discovery produces correctly-united entities for all five channels.
4. Broker unreachable degrades to retry with backoff; the UI is unaffected.
5. Disabling MQTT stops publication without a reboot.
