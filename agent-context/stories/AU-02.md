# AU-02 — CN1 I²C bus and the sensor set, proven on hardware

- **Status:** Done for SGP41; BME280 pending solder
- **Priority:** P0
- **Milestone:** Aura v1
- **Depends on:** AU-01

## User story

As the builder, I want both sensors ACKing on the only header the CYD exposes, so that the UI is
built against measured values rather than hoped-for ones.

## Outcome

One 100 kHz bus on CN1: SDA `GPIO27`, SCL `GPIO22`, 3V3 and GND. Two devices, four wires.

| Device | Address | Provides | Status |
| --- | --- | --- | --- |
| SGP41 | `0x59` | VOC Index, NOx Index | **verified** — serial `115270821`, self-test passed |
| BME280 | `0x76` | temperature, humidity, pressure | **verified on a second board**; to be soldered |

## What the bench changed about the plan

- **The gas part is an SGP41, not an SGP40.** The driver's feature probe reports `Type: SGP41`,
  so NOx Index is available and the inventory row is wrong. Correct it.
- **The first purple board is a BMP280, not a BME280** — `Wrong chip ID`. The chip-ID gate in
  `inventory.md` caught a real substitution. A second board from the same pile *is* a genuine
  BME280: 24.5 °C, 61.3 %RH, 986.0 hPa. Test every remaining board before trusting it.
- **Bus recovery matters.** ESPHome ran `Performing bus recovery` and succeeded on a bus that
  would otherwise have come up dead. This repo's own `i2c_bus.cpp` has no equivalent.

## Acceptance criteria

1. Boot scan prints `Found device at address 0x59` **and** `0x76`, and nothing else.
2. BME280 reports a chip ID of `0x60`, proven by the `bme280_i2c` platform initialising clean.
3. All five channels publish plausible values for ten consecutive cycles.
4. Pulling the pigtail mid-run produces a FAULT state, not a frozen number (see AU-03).
5. Measured CN1 pin voltages replace the community pin map in `inventory.md`.
