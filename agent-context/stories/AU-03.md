# AU-03 — Reading states and air bands: the offline-first semantics

- **Status:** Ready
- **Priority:** P0
- **Milestone:** Aura v1
- **Depends on:** AU-02

## User story

As the recipient, I want the screen to tell me when it does not know something, so that I never
read a stale number as a current one.

## Outcome

Every displayed reading carries one of four states, and the UI renders each distinguishably:

| State | Meaning | Render |
| --- | --- | --- |
| `OK` | fresh value within its update interval | the value |
| `WARMING` | sensor alive, not yet trustworthy | dimmed, with "settling" |
| `STALE` | last value older than 3 × its interval | greyed, with its age |
| `FAULT` | component marked failed or no ACK | `--`, never a number |

**The SGP41 needs `WARMING` specifically.** It reports `VOC index: 0` for its first 90 samples
while stabilising, and a literal zero on screen would read as "perfect air" — the exact inversion
of the truth. Zero during stabilisation must never reach the display as a value.

## Air bands

VOC Index is a relative scale centred on 100. Bands, and the words shown:

| VOC Index | Band | Words |
| --- | --- | --- |
| < 80 | better than normal | "Fresh" |
| 80–150 | normal | "Fine" |
| 150–250 | worse than normal | "Stuffy" |
| > 250 | much worse | "Open a window" |

The ventilation prompt is driven from VOC Index alone. There is no eCO₂ and no ppm figure
anywhere — see D-036 as amended.

## Acceptance criteria

1. A truth table for the four states is written down and matches the implementation.
2. Unplugging a sensor mid-run shows `FAULT`, not the last value.
3. The SGP41's stabilisation window shows `WARMING`, never `0`.
4. With no network at all, every sensor tile still renders — requirement G4.
5. No string containing `co2`, `CO2` or `ppm` exists in the UI or any published topic.
