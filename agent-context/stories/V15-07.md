# V15-07 — Grove descriptive four-row OLED page

- **Status:** Blocked on fresh independent review and visual hardware confirmation
- **Priority:** P1
- **Depends on:** V15-03 through V15-06 software contracts
- **Objective:** Use every row of the 128×32 OLED for a plainly labelled fitted measurement so a
  reader does not need to decode product or health-bit abbreviations.

## Scope

- Replace the normal product/name row and combined `D1B1` health row with exactly four labelled
  measurement rows: DHT11 temperature/humidity, BMP180 pressure, raw RC light time and raw soil ADC.
- Keep each row clipping-safe in the compiled 5×7 font on 128 pixels.
- Name missing values by metric and never turn unavailable into numeric zero.
- Preserve detailed serial sensor diagnostics and the separate bi-color health LED contract.
- Prove Grove MQTT state and retained Home Assistant discovery still expose exactly the five fitted
  public measurements: `temperature_c`, `humidity_pct`, `pressure_hpa`, `light_charge_us` and
  `soil_adc_raw`.

## Out of scope

- AtmosMesh v1 display/runtime changes, a product/name row, OLED menus, BMP temperature as a public
  measurement, lux/moisture calibration, MQTT topic changes, or hardware flashing.

## Acceptance criteria

- [x] Valid readings render four descriptive rows equivalent to `T:25.0C RH:36%`, `P:982.7hPa`,
  `Light:401us`, `Soil:214`, within the OLED width.
- [x] Missing/fault values explicitly retain their metric labels (`T:--`, `RH:--`, `P:ERR`,
  `Light:--`, `Soil:--`); valid numeric zero remains visible.
- [x] The normal page contains neither product/name text nor `D1B1`/other anonymous health bits.
- [x] Serial diagnostics and AtmosMesh v1 behavior remain unchanged.
- [x] Native tests prove all five Grove MQTT state keys and five truthful HA discovery objects remain
  present, with DHT11 as `temperature_c` and raw-only light/soil semantics.
- [x] Native tests, both canonical builds, compatibility builds, repository checks and secret audit
  pass before commit. No flash, self-review or merge occurs in this lane.

## Validation plan

Add failing native expectations for valid, missing, partial and numeric-zero OLED rows before
changing the formatter. Strengthen the existing Grove MQTT/discovery tests to assert the exact five
keys/object IDs. Run the full product gate matrix and record red/green evidence here.
