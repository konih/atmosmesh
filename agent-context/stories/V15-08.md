# V15-08 — Grove OLED and bi-color LED visual diagnostic image

- **Status:** Blocked on independent review and operator visual inspection
- **Priority:** P1
- **Depends on:** V15-07 compiled four-row live page
- **Objective:** Provide an explicitly selected, reversible Grove image that lights the complete
  logical 128×32 framebuffer and cycles every installed bi-color LED state for operator inspection.

## Scope

- Keep the canonical AtmosMesh Grove v1.5 build in its normal four-measurement-row mode.
- Add a separately named compile-time diagnostic build that fills all 128×32 logical pixels after
  successful OLED initialization and prevents later live rendering from overwriting the fill.
- Emit an unambiguous serial startup diagnostic with the active mode and `128x32` geometry.
- While keeping the OLED filled, repeat a slow two-second-per-phase LED sequence:
  red → green → amber (both channels) → off. Use the compiled common-cathode/common-anode polarity
  through the existing status LED mapping and log every transition with D6/D0 output levels.
- Add explicit build, flash and monitor tasks so selecting the temporary image is deliberate.
- Host-test the render policy, serial banner and LED timing/polarity including `millis()` wraparound,
  then compile normal and diagnostic Grove images.

## Out of scope

- Changing AtmosMesh v1, changing Grove wiring/controller geometry, automatically flashing a
  device, interpreting physical measurements, or making the all-white screen the product default.
- Disabling sensor or MQTT runtime work while the diagnostic image holds the OLED fill and cycles
  the LED.

## Acceptance criteria

- [x] The canonical `atmosmesh-grove-v1_5` image retains normal four-row live rendering.
- [x] The explicit diagnostic image fills the entire logical 128×32 framebuffer after successful
  OLED initialization and subsequent render calls cannot overwrite it.
- [x] Serial startup states that the full-area diagnostic is active and names geometry `128x32`.
- [x] Diagnostic-only LED output repeats red → green → amber → off every two seconds, uses the
  compiled polarity, survives timer wraparound and logs each expected color plus D6/D0 levels.
- [x] The canonical Grove image retains its sensor/MQTT-driven status LED policy unchanged.
- [x] Dedicated, descriptively named build/flash/monitor tasks are documented; no flash occurs in
  this implementation lane.
- [x] Native red/green evidence and the full product gate matrix are recorded before commit.

## Validation plan

Add failing native tests for the default/diagnostic render policy and exact diagnostic banner before
production behavior. Add red tests for the four-phase LED timeline, wraparound and both polarities
before wiring the policy into the Grove loop. Build the canonical Grove environment and inspect its
compile command/default policy, then build the dedicated diagnostic environment with its explicit
flag. Run native tests, both first-class product builds, compatibility builds, repository checks
and the secret audit. A later independently reviewed operator run may leave the diagnostic running
until the operator explicitly requests restoration of the canonical Grove image.
