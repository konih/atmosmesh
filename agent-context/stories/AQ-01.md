# AQ-01 — AtmosMesh Aqua bring-up: SHT41 + genuine 128×64 OLED + duty-cycled water probe

- **Status:** In flight — software merged to `main`; hardware soldered, wired and flashed. SHT41,
  water probe, WiFi and MQTT all confirmed working over serial. The OLED module is diagnosed
  faulty/DOA (see Evidence) — every wiring-side cause was individually ruled out by direct
  measurement; blocked on a replacement module, not on firmware. Acceptance criterion 1
  (photographed board/probe evidence) was **not** satisfied as originally written (photo before
  wiring, independent review before flash) — see Evidence for what actually happened instead and
  why.
- **Priority:** P2
- **Milestone:** Aqua-M1 — Hardware approved (new; mirrors RLS-01/V15-01 for this third product)
- **Depends on:** ADR-0001 (product composition pattern), D-002/D-010/D-015 (raw-value labeling
  and single-ADC-channel discipline), D-019/ADR-0002 (MQTT-only transport for this variant),
  D-020 (Aqua OLED page layout)

## User story

As the operator bringing up new hardware, I want a new AtmosMesh product composition root for the
ESP8266MOD + SHT41 + 128×64 OLED + water-probe board, so that it gets the same reviewed,
host-tested, ID-based contract as AtmosMesh v1 and Grove v1.5 without duplicating or destabilizing
either.

## Outcome

A new, independently buildable product (`atmosmesh-aqua-v1`) publishes raw SHT41 temperature/
humidity and a raw, explicitly-uncalibrated water-probe ADC diagnostic over the existing MQTT
contract, on a genuine 128×64 local display, without touching AtmosMesh v1 or Grove v1.5.

## In scope

- New `ProductProfile` entry with I2C bus on `D2`/GPIO4 (SDA) and `D1`/GPIO5 (SCL) — the ESP8266
  Arduino core's default `Wire` pins, chosen to avoid GPIO0/GPIO2's boot-strap hazard that D-009
  had to document and work around for Grove.
- SHT41 on that bus at I2C address `0x44` (Sensirion default).
- A genuine SSD1306-class 128×64 panel on the same bus, address preference `0x3C` then `0x3D`
  (D-001/D-006 convention). Reuse AtmosMesh v1's existing 128×64 U8g2 constructor/composition-
  boundary code rather than inventing a second 128×64 constructor path — the "small compile-time
  adapter at a composition boundary" ADR-0001 permits.
- A new `water_power_control_gpio` profile field on `D5`/GPIO14 (free — DHT is dropped) driving a
  high-side PNP switch mirroring D-015's proven pattern (2N3906, emitter=3V3, collector=probe VCC,
  base through ~2.2 kΩ, external 100 kΩ base-emitter pull-up, active LOW, fail-safe HIGH/OFF
  established before `pinMode(OUTPUT)`). This is mandatory, not optional — a wetted probe corrodes
  at least as readily as YL-38's soil contacts, so D-015's duty-cycling argument applies with equal
  or greater force.
- Do not overload the existing `soil_power_control_gpio` field name for a water sensor — add a
  distinctly-named field. AtmosMesh v1 and Grove v1.5 leave it at the existing `-1` sentinel, same
  as they already do for fields they don't use.
- Water probe AOUT → `A0` (ESP8266's single ADC channel), reusing D-015's 30 s start-to-start /
  100 ms settle / bounded-averaged-sample cadence as a starting default, not final until the
  probe's actual output range is confirmed (see Open questions). Reported as `water_adc_raw` only
  — never `water_level`, never a percent, never "moisture."
- New `MqttProductKind::AtmosMeshAquaV1` contract: topics `home/air/atmosmesh-aqua-0001/state` and
  `.../availability`, discovery node `atmosmesh_aqua_0001`, three discovery entities
  (`temperature_c`, `humidity_pct`, `water_adc_raw`) — no pressure entity (SHT41 does not measure
  pressure; do not carry Grove's `pressure_hpa` field into this product).
- Grove v1.5's soil sensor pattern is **not** reused by this product. The single ADC channel is
  dedicated entirely to the water probe. Grove v1.5's own composition root, profile, and soil
  sampler are unchanged.
- A new OLED page-layout decision (new decision number, not an amendment of D-016 — D-016 is bound
  to Grove's 128×32 geometry and does not extend to other products). Default proposal: reuse a
  4-row descriptive layout (temperature, humidity, water raw ADC, one spare/status row), taking
  advantage of the doubled vertical resolution for a larger, more legible font rather than packing
  8 thin rows — pin this down in acceptance criteria, not by assumption.

## Out of scope

- DHT11/BMP180 hardware or drivers (SHT41 replaces them for this product only).
- Reusing Grove's soil sensor physically or its `soil_adc_raw` field name.
- A status LED (D-014-style) — not requested for this variant; may be a later story.
- Moisture/water-level calibration, percentage, or any derived "level" claim.
- ESPHome native API transport — declined by D-019/ADR-0002 for this cycle.
- Any change to AtmosMesh v1 or Grove v1.5 pins/runtime/behavior.

## Open questions this story does not close (hard gate before wiring/flashing)

1. **Board identity.** "ESP8266MOD" is the silkscreen on the ESP-12E/12F module, not a specific
   board design. It could be a bare module breakout with no onboard USB-serial/regulator/boot-
   strap resistors, or a NodeMCU-style devboard (what Grove v1.5 already is). Do not assume —
   photograph and confirm before wiring, exactly as D-009 did for Grove. The pin table above
   assumes NodeMCU-style as the likely case, matching the operator's other hardware, but is not
   binding until confirmed.
2. **Water probe identity.** A 3-pin VCC/GND/AOUT device with no DO pin is probably not a YL-38 —
   YL-38 is a 4-pin comparator carrier (VCC/GND/DO/AO) built around an LM393 comparator with a
   trim pot. Check for an LM393 chip and trimpot on the probe board. If absent, it is more likely a
   bare resistive probe strip whose "AOUT" is a raw divider node — a different electrical model
   with a different dry/wet voltage range. D-010's rule still binds regardless of which it is:
   confirm the exact board's onboard A0 divider (if any) and the probe's dry/wet AOUT range at
   3.3 V before connecting anything to A0. Do not copy Grove's divider without re-deriving it for
   this specific probe and board.
3. Final 30 s/100 ms/sample-count cadence values are provisional until (2) is resolved — a
   different probe's electrical/corrosion characteristics may justify different numbers.

## Validation

- **Automated:** Failing host tests first for profile field values/sentinels, SHT41 reading
  validity/invalidation, water-probe sampler timing (reuse/extend the soil sampler's tested state
  machine shape), new discovery entity count/labels, and the "no pressure entity" contract. Then
  `task test`, new canonical build, all existing canonical/compatibility builds, `task check`.
- **Manual:** Photograph board/probe identity before wiring (open questions 1–2). Bench-run all
  sensors together, confirm OLED renders all four rows without truncation, confirm MQTT discovery
  appears correctly in Home Assistant.
- **Failure/edge case:** SHT41 read failure shows "unavailable," not zero. Water probe stays
  powered off except during its sample window. No flash without independent review.
